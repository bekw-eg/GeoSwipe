# Геометрический движок

Движок рассчитан на математические условия, а не на заданное положение фигуры. Весь `lib/core/geometry/` можно использовать без Flutter. Виджеты, локальное сохранение прогресса и каталог задач используют ту же модель.

## Слои

- `geometry.dart`: `GeoPoint`, `GeoTriangle`, расстояния, углы между векторами, внутренние углы, прямой угол, площадь, обе формулы Пифагора, подобие SSS и `sin/cos/tan` при выбранной острой вершине прямоугольного треугольника.
- `scene.dart`: неизменяемые точки с идентификаторами, отрезки, лучи, треугольники и дуги. Объекты ссылаются на общие точки: перемещение вершины обновляет все связанные фигуры. `draggable` выбирает подвижные точки; `GeoRay.rotatable` задаёт вращение с сохранением длины ручки. Границы поля задаются явно и не меняются при перетаскивании.
- `constraints.dart`: `GeometryConstraint.check(scene, answer: ...)` возвращает результат и обратную связь. `AngleConstraint` проверяет обычный или направленный угол, `RightTriangleConstraint` — наличие прямого угла при любой вершине, `NumericAnswerConstraint` — число с абсолютным допуском. `AllConstraints` требует выполнения всех переданных условий. Пустая композиция запрещена.
- `GeometryViewport`: обратимые преобразования между математическими координатами (Y вверх) и локальными экранными (Y вниз), одинаковый масштаб по осям и поля для подписей. Свободное место на вытянутом экране не растягивает фигуры.
- `GeometryBoard`: выбор ближайшей ручки в радиусе 32 логических пикселей, сохранение смещения пальца относительно точки, ограничение свободного перемещения границами сцены. Ручка сразу получает жест; остальная область остаётся доступной для прокрутки. Второе касание не переключает активную ручку. Для вращения предусмотрена мёртвая зона 16 пикселей вокруг вершины.
- `GeometryPainter`: отображение фигур, стрелок лучей, дуг, градусов, подписей точек и длин сторон. Он не решает, выполнена ли задача. `showLength: false` и явная подпись `?` скрывают неизвестную длину.

`PuzzleCard` содержит условие, результат проверки, подсказку, повторную попытку и переход дальше. Внутри него выбирается механика `RotatePuzzle`, `DragPuzzle` или `AnswerPuzzle`. Текст поля ответа задаётся через `Level.answerLabel`. Завершённую попытку нельзя зачесть повторно; новая попытка восстанавливает исходную сцену и очищает ввод. Объяснение появляется после верного ответа.

## Числа и некорректные фигуры

Все координаты измеряются в единицах задачи. Экранные пиксели не участвуют в проверке.

- Нулевые и нечисловые векторы не имеют угла. Для длин используется порог `1e-9` единиц; треугольник считается вырожденным также при нормированной удвоенной площади не больше `1e-10`. Нормировка выполняется по квадрату наибольшей стороны.
- Неопределённые вычисления возвращают `null`, предикаты — `false`. Площадь вырожденного треугольника возвращает `null`, чтобы такой объект нельзя было принять как допустимый треугольник с площадью 0. Непредставимые конечным `double` результаты также возвращают `null`.
- Длины и направления нормируются до умножения и возведения в квадрат, чтобы промежуточные значения не переполнялись. Углы вычисляются через `atan2`, включая почти параллельные направления.
- `hypotenuse` требует два положительных ненулевых катета; `missingLeg` — гипотенузу больше известного положительного катета. `isPythagorean` не зависит от порядка сторон.
- Подобие сравнивает отсортированные отношения сторон с относительным допуском `1e-6`. Сдвиг, масштаб, отражение и порядок вершин не влияют на результат.
- `rightTriangleTrig(triangle, vertex)` использует вершины 0=A, 1=B, 2=C. Для прямой вершины, непрямоугольного или вырожденного треугольника возвращается `null`; деление на ноль исключается.
- В демонстрационных задачах допустимы угловые ошибки **±2°** и численная ошибка **±0,01**. Границы включены, технический epsilon равен `1e-9`. Проверяются исходные значения, а не округлённые подписи. Численный ввод принимает точку, запятую и внешние пробелы; NaN и бесконечности отклоняются.

Сцена проверяет конечность координат, существование ссылок и корректность границ. Начальный поворачиваемый луч должен иметь ненулевую конечную длину. Свободные вершины треугольника могут совпасть или оказаться на прямой: UI продолжит работать, проверка объяснит вырождение.

## Добавление задач

Новая задача добавляется в `level_catalog.dart`; её стабильный ID нужно также включить в `MathTopic.levelIds`. Схема сохранения не меняется. Пример треугольника, в котором можно двигать все три вершины:

```dart
Level(
  id: 'triangle-free-right',
  topicId: 'triangles',
  title: 'Свободное построение',
  kind: PuzzleKind.dragVertices,
  goalLabel: '90°',
  instruction: 'Построй любой прямоугольный треугольник.',
  hint: 'Две стороны должны быть перпендикулярны.',
  explanation: 'Один угол равен 90°, два других в сумме дают 90°.',
  initialScene: GeometryScene(
    points: const {
      'A': GeoPoint(-3, -2),
      'B': GeoPoint(3, -2),
      'C': GeoPoint(1, 3),
    },
    triangles: const [TriangleRef('A', 'B', 'C')],
    draggable: const {'A', 'B', 'C'},
  ),
  constraint: const RightTriangleConstraint(TriangleRef('A', 'B', 'C')),
)
```

Для нового математического условия реализуйте `GeometryConstraint`, используя чистые функции `Geometry`; передайте его в `Level.constraint`. Составные задачи используют `AllConstraints`. Для нового численного задания передайте вычисленное значение в `NumericAnswerConstraint`, задайте соответствующую сцену и подпись ввода. Новые ограничения не требуют изменений в painter, механизмах проверки попыток или хранилище.

Существующие угловые уровни продолжают задаваться через `initialAngle`, `targetAngle`, `tolerance`: `Level` строит из них обычную сцену и `AngleConstraint`. `AngleBoard` оставлен как совместимый адаптер общего поля.

## Демонстрации и проверка

1. `angle-60`: направленный угол 60°, ручка луча и ползунок, проверка и повторная попытка.
2. `triangle-right`: перемещение C относительно фиксированных A и B. Принимаются углы при A, B или C, в том числе отражённые решения; совпадение с одной эталонной позицией не требуется.
3. `pythagoras-3-4`: катеты 3 и 4, неизвестная гипотенуза, численный ввод, проверка без показа ответа до решения.

Примеры этого раздела описывают исходную версию движка. В текущем курсе используются ID `angle-45`, `triangle-right`, `pythagoras-3-4`; прежний `angle-60` снят с каталога, его данные сохраняются. Правила обучения и схема сохранения version 2 описаны в [обучающей системе](learning-system.md). Координаты и незавершённый ввод живут в текущем сеансе; использованные подсказки восстанавливаются после перезапуска. В повторении неподвижный луч OA может иметь другое исходное направление; ползунок и `PuzzleState.angle` отсчитывают поворот от OA.

Рендеры для экрана 390 × 1000: [поворот луча](screenshots/engine-rotate.png), [перемещение вершины](screenshots/engine-drag.png), [численный ответ](screenshots/engine-answer.png).

Unit-тесты проверяют формулы, граничные случаи и математические ограничения. Виджетные тесты двигают ручки, проходят задачи, проверяют ввод, перезапуск, разные соотношения сторон поля, компактный/горизонтальный экран и крупный текст. Отдельный тест проверяет сохранение прогресса и повторение новых механик. Изображения в `build/ui/engine-*.png` — рендеры виджетных тестов, не эталон проверки по пикселям. Тест на физическом Android-устройстве отдельно не выполнялся.
